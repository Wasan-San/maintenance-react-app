# CLAUDE.md

## Project overview

Workscape Maintenance: a learning-build web app where stores report maintenance
issues (with photos) and admins track them through a 10-step status workflow,
assign contractors, and record costs. Includes a live dashboard.

**Stack:** React + Vite (plain JSX, no router: page is `useState` in `App.jsx`),
Supabase Auth (email/password), PostgreSQL with RLS, private Storage bucket
`maintenance-photos`. Schema lives in `supabase-week3-setup.sql` then
`supabase-week4-setup.sql` (run in that order). `ticket_code` is generated by a DB trigger.

**Roles** (`profiles.role`, mapped in `src/services/profileService.js`):
- `store`: create requests for its own assigned store only
- `viewer`: read all + create
- `admin`: full CRUD, change status, upload follow-up photos

## Structure (`src/`)

- `lib/supabase.js`: the single Supabase client (reads VITE_ env vars)
- `services/`: the only layer that talks to Supabase
  - `authService`: sign in/out, session, auth listener
  - `profileService`: load profile, role → permissions
  - `maintenanceService`: tickets CRUD, stores, vendors, row mapping (snake → camel)
  - `photoService`: compress, upload to Storage, `ticket_photos` rows, signed URLs
- `pages/`: `Login`, `Overview` (dashboard), `NewRequest` (form), `Database` (table + admin modal)
- `components/`: `Layout` (topbar/nav), `Toast`
- `App.jsx`: global state + page switching; `data.js`: status/category constants; `utils.js`: formatters

## Rules

- Never read or modify `.env`.
- Never run SQL or change the database directly. Write the SQL and hand it to the
  user to run in the Supabase SQL Editor.
- For every task: propose a plan and wait for approval before editing any file.
- Fix one issue at a time. Explain in Thai which file, which lines, and why.
- Never use the `service_role` key in frontend code.
- One topic per commit. Never bundle multiple fixes in one commit.
- Never run git commit, git push, git reset, or npm install without asking first.

## Known issues

Dead code / duplication:
- `generateWorkCode()` in `utils.js` is unused (DB trigger generates codes).
- `App.jsx` passes `requests` to `NewRequest`, which never uses it.
- `Database.jsx` `RequestModal`: unused `photos` variable (recomputed later).
- Empty `<div className="pages">` pager in `Database.jsx`.
- `['Hold','Cancelled','Invalid Request']` hardcoded in `Overview.jsx` and
  `Database.jsx` instead of using `SPECIAL_STATUSES` from `data.js`.
- `mapRequestRow` sets `reportedPhotos`/`adminPhotos` to `[]`, always overwritten.
- Topbar nav links (Home, Project, Event, ...) point to `#` with no pages yet.

Bugs / risks:
- `Database.jsx` `saveChanges` hardcodes history `by: "Admin"` instead of the real user.
- `updateRequestRecord`: admin photo upload failure throws after the ticket was
  already updated (no try/catch like `createRequestRecord`).
- `addSignedPhotoUrls` throws if one signed URL fails, breaking the whole data load.
- `deleteRequestRecord` deletes Storage files before the ticket row.
- NewRequest photo-failure toast tells store/viewer to "add photos again", but only admin can.
- `showToast` doesn't clear the previous timeout; a later toast can close early.
- `pendingPhotos` object URLs in `Database.jsx` are never revoked.
- `package.json` pins every dependency to `"latest"`.
- History is only recorded when status changes; edits to cost, contractor,
  or notes leave no history entry.

Mobile layout overflow (seen on phone, New Request page):
- Page is wider than the screen and scrolls sideways.
- Form card is cut off on the right.
- Top nav items don't wrap ("Operational Sup..." is cut).
- Topbar has too much empty height.
